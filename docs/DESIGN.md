# MSM Helper 设计文档

[English](DESIGN.en.md) | **简体中文** | [返回主页 README.md](../README.md)

本文档系统阐述《My Singing Monsters》后台自动化助手（MSM Helper）的架构设计、底层系统原理、计算机视觉感知契约、参数实测标定方法论及关键 Bug 的技术复盘。

> **开发模式声明**：本项目采用现代人机协作（Human-in-the-Loop）开发模式。

| 协同角色 | 核心职责与工程输入 |
| :--- | :--- |
| **人类开发者**（主导） | 制定工程演进与开发路径、确立系统分层与安全红线、提出最坏构造与上界数学证明、提供实机物理现象观察、负责真实游戏数据录制与实机最终验收。 |
| **AI Agent**（赋能） | 协助算法状态机代码落地与测试用例编写、构建 472 项无头单元与集成测试套件、执行感知参数统计分离度分析与自动化工具链建设。 |

## 1. 设计原则

本项目的首要设计原则是**对宿主操作系统的零侵扰性**，即脚本运行时绝不影响用户正常使用电脑。由此衍生出四条不可协商的底层工程约束：

| 约束维度 | 具体实现 | 原理与机制 |
| :--- | :--- | :--- |
| **后台画面截取** | `PrintWindow(hwnd, hdc, PW_CLIENTONLY \| PW_RENDERFULLCONTENT)` | flag 3 (`PW_RENDERFULLCONTENT`) 是读取 DirectX 硬件加速渲染画面的前提，避免截取到黑屏。 |
| **后台动作投递** | `SendMessage(hwnd, WM_LBUTTONDOWN / WM_LBUTTONUP, ...)` | 将输入事件直接投递给游戏窗口消息队列，无需激活窗口。 |
| **禁止物理鼠标劫持** | 严禁调用 `SetCursorPos` / `mouse_event` / `SendInput` | 绝不争夺物理鼠标控制权，用户可同时在其他窗口操作。 |
| **禁止焦点抢占** | 严禁调用 `SetForegroundWindow` / `SetActiveWindow` | 游戏窗口可被遮挡、可置于后台，绝不抢夺前台焦点。 |

> **系统物理限制**：游戏窗口不能最小化（Minimized）。当窗口最小化后，Windows DWM 将暂停其客户区的渲染流水线以节约 GPU 资源，此时任何后台截图 API 都无法获取有效帧。这属于操作系统设计限制，不影响后台被遮挡运行的成立。

任何“依赖维持前台窗口”的方案在本项目中均被视为架构性错误。

## 3. 感知参数

本项目的核心工程纪律：**严禁凭空设定感知参数，所有阈值必须基于真实录制数据集（`captures/`）进行统计测量与双向分离度验证。**

### 核心感知参数标定表

| 核心参数 | 标定取值 | 实测依据与统计分离度 |
| :--- | :--- | :--- |
| `reference_size` | `(1024, 768)` | 游戏基准渲染分辨率，所有相对坐标与尺寸换算的锚点。 |
| `match_threshold` | `0.75` | 金币模板匹配相似度分布：完整可见 $0.80 \sim 0.98$（$p_{50}=0.80, p_{95}=0.89$）；遮挡下掉至 $0.51$。$0.75$ 是兼顾召回与假阳性的最佳分割线。 |
| `nms_distance` | `30 px` | 真实紧邻金币牌间距下界为 $38.6\text{px}$，跨尺度重复检出距离近至 $26\text{px}$。$30\text{px}$ 落在两者之间，既抑制重叠又防止误合相邻目标。 |
| `match_downscale` | `0.5` | 耗时从 $103\sim 108\text{ms}$ 压降至 $30\sim 48\text{ms}$（提速 $2.5\times$），漏检率仅 $1.8\%$，中心漂移 $\le 2\text{px}$；而 $0.4$ 降采样漏检率骤增至 $4.5\%$。 |
| 卡背填充率 (`min_fill`) | `0.70` | 真实紫色卡背填充率 $0.89 \sim 0.97$；卡面内部误检紫色色块填充率 $0.49$。$0.70$ 处于中心，两侧各有 $\approx 0.20$ 的安全余量。 |
| 卡面相似度 (`similarity`) | `0.75` | 真实匹配对相似度 $p_5=0.92, \text{median}=0.9827$；非匹配对最大值仅 $0.4618$。稳健间隙达 $+0.2333$，因错配惩罚极大而取保守阈值 $0.75$。 |
| 卡面稳定性 (`stability`) | `0.98` | 卡面为静态位图，静止帧自相关系数**严格等于 1.000**；翻转动画期间降至 $0.21 \sim 0.93$。$0.98$ 成为最可靠的动画结束判据。 |

### 被实验数据否决的方案（Negative Results）

记录被否决的方案是工程设计的重要财富：

- **纹理探测规则（`require_texture_below`）**：原意检测金币下方是否存在怪兽纹理。实测 219 个真实目标探测值分布在 $41.8 \sim 72.4$（预设阈值 $12.0$），拒绝率为 $0\%$ 且缺乏负样本分离度。诚实的做法是直接禁用而非伪造阈值。
- **裁剪搜索区域（ROI Cropping）**：试图仅匹配游戏主岛区域以减少像素。实测耗时 $105\sim 129\text{ms}$，慢于全屏匹配的 $103\sim 108\text{ms}$。原因是内存非连续视图复制与切片开销超过了减少 $25\%$ 像素带来的收益。
- **基于颜色阈值的“发光代理指标”**：曾尝试通过黄色/绿色色相检测卡牌发光动画。实测金色/琥珀色卡面（金币、XP 星）自身即命中发光区间，导致整关死锁。教训是**永远不要用代理指标去判断一件可以直接测量的事物（帧间稳定性）**。

## 4. 记忆小游戏算法与状态机

记忆翻牌小游戏的难点在于：**非固定布局、卡面图案种类繁多、失配存在代价。**

### 4.1 算法设计
1. **跨尺度 HSV 卡背检测**：卡背在各关卡尺寸变化达 $1.9\times$（$63\text{px} \sim 122\text{px}$）。通过颜色空间分割提取卡背轮廓，天然尺度无关。
2. **行带聚类（Row-band Clustering）**：任意多边形分布的卡牌，通过 $y$ 坐标密度聚类识别“视觉行”，行内按 $x$ 排序，精准还原人类自然阅读顺序。
3. **运行时卡面聚类（`FaceRegistry`）**：截取卡面内缩 $18\%$ 并归一化至 $48\times 48$，保留颜色特征，通过皮尔逊相关系数运行时动态归类。

### 4.2 失配上界与机会数的数学证明
设盘面有 $n$ 对卡牌（共 $2n$ 张）：
- 游戏给予机会数公式为：$\text{Chances} = \lceil 1.5 \times n \rceil$
- 状态机在最坏牌序构造（`AB | CA | DB | EC | ...`）下的失配次数为：
  $$\text{Max Mismatches} \le 1 + (n - 2) = n - 1$$
- 证明表明系统剩余约 $50\%$ 的容错余量，只要感知不发生两两错配，数学上保证 $100\%$ 通关。

### 4.3 并发读取优化
在“先全部翻开”策略中，两张牌的翻开本质是两次独立读取。系统优化为：**连点两张 $\rightarrow$ 等待单次稳定沉降 $\rightarrow$ 同步解析两张卡面**。单轮等待开销减少 $50\%$，实机翻牌平均耗时压缩至约 $1.10\text{s}/\text{card}$（耗时主要受限于游戏自身的翻转动画）。优化代价：仅仅是比保守配对的最坏情况要多一次失配次数。

## 5. 四个关键 Bug 技术复盘

单元测试与静态帧回放均未暴露这四个问题，唯有真实游戏环境下才会显现：

### 1. DPI 感知不一致（Coordinate Space Skew）
- **现象**：在 $150\%$ 系统缩放下，点击完全偏离目标。
- **根因**：`QApplication` 初始化后将主进程标记为 System DPI-Aware，导致 `GetClientRect` 返回缩放后的虚拟分辨率（如 $1536\times 1152$），而游戏引擎实际在未缩放的客户区（$1024\times 768$）渲染。
- **解法**：建立 `dpi_unaware_thread()` 上下文管理器，在执行截图与坐标换算时临时切入目标 DPI 空间，保持两端坐标系统严格对齐。

### 2. 卡面内部紫色误识别（Fill Ratio Filter）
- **现象**：翻开的怪兽卡面内部有紫色色块，导致系统误判该槽位“仍是背面”，引发翻牌死循环。
- **根因**：紫色怪兽局部的 HSV 色相与长宽比均在卡背容差内。
- **解法**：引入多边形包围盒填充率指标（`min_fill`），真卡背为饱满矩形（$\ge 0.89$），局部碎片仅为 $0.49$，设立 $0.70$ 阈值彻底隔离。

### 3. 关卡切换瞬态竞态（Level Transition Race）
- **现象**：当第 1 关出现 `AABB` 牌序时，两轮连续配对成功，整关耗时不足 $1.5\text{s}$。系统下一帧报错 `GEOMETRY_DRIFT`（检出 6 张卡牌但槽位表仅 4 个）并异常停机。
- **根因**：运行器反应速度极快，关卡已瞬间结束并载入了下一关的新盘面，而运行器仍拿新盘面比对旧关卡槽位表。
- **解法**：遵循“记录优先于盘面”原则。决策循环前优先询问 `solver.is_solved()`，若所有配对已完成则直接结关，不截取失效画面。

### 4. 偶发误触的物理指针干扰假说
- **现象**：偶发点到岛屿建筑导致镜头滑动。
- **根因分析**：后台投递伪造鼠标移动与按下消息时存在极短时钟缝隙（$8\sim 25\text{ms}$）。若此时用户在物理屏幕上快速移动鼠标，操作系统真实的 `WM_MOUSEMOVE` 会穿透给窗口，导致游戏内部指针被带走。
- **解法**：架构中设立指针运动安全门，并记录于深入研究文档。
